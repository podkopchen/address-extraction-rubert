# Address Extraction RuBERT

Проект для извлечения адресных компонентов из русскоязычных обращений граждан с помощью RuBERT NER-модели.

Модель решает задачу **token classification / NER** и выделяет компоненты адреса в грязном неструктурированном тексте.

## Возможности

Модель выделяет следующие компоненты:

- `REGION` — регион / область / край;
- `CITY` — город;
- `SETTLEMENT` — поселок, деревня, СНТ, ДНП и другие населенные пункты;
- `DISTRICT` — район;
- `STREET` — улица, проспект, шоссе, бульвар, переулок, проезд и т.д.;
- `HOUSE` — дом;
- `CORPUS` — корпус;
- `BUILDING` — строение;
- `ENTRANCE` — подъезд;
- `FLAT` — квартира.

Пример входного текста:

```text
Здравствуйте, у нас на Старомонетной 18 опять течет крыша, никто не приходит.
```

Ожидаемые компоненты:

```text
STREET: Старомонетной
HOUSE: 18
```

## Назначение проекта

Проект предназначен для обработки обращений граждан, в которых адрес может быть указан неформально, неполно или с ошибками.

Типовые особенности входного текста:

- адрес написан без города;
- отсутствует слово «улица»;
- адрес находится в середине длинного обращения;
- используются разговорные формулировки;
- присутствуют ошибки, повторы и плохая пунктуация;
- в тексте есть лишние числа: даты, номера заявок, этажи, суммы, годы;
- встречаются ФИО, похожие на названия улиц.

Примеры:

```text
у нас на Андропова 60 корпус 2 не работает лифт
```

```text
г. Сочи, улица Ленина, дом 10 корпус 2, квартира 45, нет отопления
```

```text
Московская область, поселок Развилка, улица Центральная, д. 5, не вывозят мусор
```

## Архитектура решения

Общая схема обработки:

```text
текст обращения
    ↓
RuBERT NER
    ↓
адресные компоненты
    ↓
post-processing
    ↓
нормализованный адрес
    ↓
DaData / ФИАС / внутренняя адресная система
```

Важно: RuBERT-модель **не является полноценным нормализатором адресов**.

Она отвечает за извлечение адресных компонентов из текста. Приведение к эталонному виду, определение индекса, округа, района, координат и проверка существования адреса должны выполняться отдельным слоем нормализации, например через DaData, ФИАС или внутренний адресный справочник.

## Что не хранится в репозитории

В репозиторий намеренно не добавляются:

- Excel-файлы с обращениями;
- результаты обработки;
- реальные датасеты;
- синтетические датасеты;
- веса модели;
- checkpoint-папки;
- `model.safetensors`;
- архивы модели.

Модель рекомендуется распространять отдельно через **GitHub Releases** или внутреннее файловое хранилище.

## Установка

Создать виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install --upgrade pip
```

Установить зависимости:

```powershell
pip install -r requirements.txt
```

Для CPU-инференса PyTorch можно установить отдельно:

```powershell
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

## Подготовка к запуску

В корневую папку проекта необходимо положить Excel-файл с обращениями:

```text
Обращения_Адрес_район_округ.xlsx
```

Также рядом должна находиться папка с обученной моделью:

```text
address_ner_rubert_conversational_v1/
```

Папка модели должна содержать файлы HuggingFace-модели:

```text
config.json
model.safetensors
tokenizer.json
tokenizer_config.json
training_args.bin
training_metadata.json
```

Excel-файл должен содержать колонки:

```text
Обращение заявителя
Выделенный адрес(а)
```

## Запуск

```powershell
python test.py
```

После выполнения будет создан файл:

```text
Результат_RuBERT_адреса.xlsx
```

В выходном файле формируются колонки:

- `№`;
- `Обращение заявителя`;
- `Выделенный адрес(а)`;
- `Адресс rubert`;
- `Сравнение`;
- `Компоненты rubert`.

## Пример результата

Входной текст:

```text
Живу на улице Андропова 60 корпус 2, первый подъезд, не работает лифт.
```

Компоненты модели:

```text
STREET: улице Андропова
HOUSE: 60
CORPUS: корпус 2
```

После post-processing результат может быть приведен к виду:

```text
ул. Андропова, д. 60, к. 2
```

## Сравнение с ручной разметкой

Скрипт сравнивает результат модели с колонкой `Выделенный адрес(а)` и присваивает один из статусов:

- `полное совпадение`;
- `похоже`;
- `частично похоже`;
- `rubert шире`;
- `ручной шире`;
- `rubert пусто`;
- `rubert нашел, вручную пусто`;
- `оба пусто`;
- `разное`.

Это сравнение является вспомогательным. Оно не заменяет полноценную оценку NER-модели по BIO-разметке, но помогает быстро проверить работу модели на Excel-таблице.

## Текущий статус

Проект находится на стадии рабочего прототипа.

Модель уже умеет:

- находить улицу и дом в грязном тексте;
- находить адрес без явно указанного города;
- не реагировать на большинство бытовых чисел;
- выделять город, регион, поселение и район;
- извлекать корпус, строение, подъезд и квартиру;
- работать с длинными обращениями через разбиение на чанки.

Основные направления дальнейшей доработки:

- улучшение post-processing;
- перевод русских числительных в цифры;
- удаление дублей компонентов;
- обработка нескольких адресов в одном обращении;
- улучшение нормализации улиц и домов;
- интеграция с DaData / ФИАС;
- расширение реального датасета;
- дополнительное обучение на новых ошибках.

## Рекомендуемый production-пайплайн

```text
1. Получить текст обращения.
2. Прогнать текст через RuBERT NER.
3. Извлечь компоненты адреса.
4. Очистить компоненты через post-processing.
5. Передать адресный фрагмент в DaData / ФИАС.
6. Получить нормализованный адрес, индекс, район, округ и координаты.
7. Сохранить результат в целевую систему.
```

## Примечание

Если в тексте обращения не указан город, модель не должна автоматически добавлять `г. Москва`. Город, регион, район и прочие географические атрибуты должны добавляться только после нормализации через внешний адресный справочник или сервис.
